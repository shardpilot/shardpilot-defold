# A5 baseline — Defold SDK, before C3's automatic lifecycle events

- Date: **2026-08-28**
- Commit measured: `cf0c2189f983745ab80f4eff14754f69af3d9ec0` (`origin/main`)
- Runtime: `LuaJIT 2.1.1785577137 -- Copyright (C) 2005-2026 Mike Pall. https://luajit.org/`
- Machine: Apple M1 Max, 10 CPUs, macOS 26.5.2 — a laptop, not a device and not CI
- Produced by: `luajit test/bench_spool_append.lua`

## Why now

C3 adds automatic lifecycle events. Every automatic event is another spool
append and another queued envelope, so **the cost of an append before automatic
collection is measurable only until C3 lands.** Afterwards there is nowhere left
to measure it.

## Numbers

```

n=2000  min 0.013  p50 0.020  p95 0.065  p99 0.117  max 0.346 ms
mean 0.027 ms   total 53.8 ms across 2000 spooling appends
p95 empty(first 100) 0.081 ms   p95 full(last 100) 0.100 ms   ratio 1.2x
sys.save calls 2002   entries handed to sys.save 875250 (437.6 per append)
json.encode calls 2000 (1.0 per append) -- every entry re-encoded, every time
```

## What this establishes

**Append cost does not grow with backlog.** p95 on the last 100 appends is
1.2× the p95 on the first 100, against a backlog that went from empty to the
500-entry cap. That is the append-only property from `#59` holding under
sustained overflow, measured rather than asserted.

The absolute figures — p50 0.020 ms, p95 0.065 ms, mean 0.027 ms — are the
number C3 will move, because C3 multiplies the number of appends per session,
not the cost of one.

## What it does NOT establish, and this is the larger half

**This harness measures spool-append latency, which is an A6-era axis.** It does
not measure the axes C3 moves most directly: allocations per `track()`, batching
cadence, or events per session. Those have no harness in this SDK, and building
one is A5's own `Do` step rather than something this baseline could borrow.

The harness's own caveat is inherited and repeated here rather than buried: its
`sys.save` mock **stores a reference and returns without serializing**, so every
figure above is the SDK's own Lua work with the engine's durable write excluded.
These are not end-to-end frame costs.

## Axes not varied

One machine (a laptop — not an Android or iOS device, which is where the
question studios ask actually lives), one runtime (LuaJIT, not the Defold
engine's own VM), one run (no repetition, so **no variance figure** — unlike the
Go baseline, where two runs showed `ns/op` moving up to 64%; treat every
millisecond here as a single sample), one config, one append shape (one envelope
per append, which is what a full queue produces).
